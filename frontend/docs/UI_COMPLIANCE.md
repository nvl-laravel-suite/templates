# UI compliance review

The current integration targets Themelia React UI **2.0.5** and official **Base UI ^1.9.0**. The original **2026-10-23** ownership review covered Themelia **2.0.1**, **74 reachable UI files**, **1,191 JSX sites**, **25 public import families** and **155 application CSS rules**. Those counts and the earlier verification evidence below describe that baseline; the machine inventory and hash-bound ledger determine current source coverage.

Use [UI integration](UI.md) for the application policy and [the installed consumer skill](../.agents/skills/themelia-react-ui-consumer/SKILL.md) for the upstream rules. The [machine inventory](ui-compliance.inventory.json) contains each JSX site's file/line, owning import/local adapter/native tag, every prop name and a short source excerpt, plus every CSS selector/declaration. Source hashes bind those excerpts to the complete files. The [review ledger](ui-compliance.review.json) stores the manually authored decisions below and their fingerprints.

## Themelia 2.0.5 contextual update

The current pass records the incentive, essence, actual records, authority and ranked reading order for each view/component family before choosing composition owners. Repository design briefs distinguish active chrome, authored renderers, supplied examples and dormant scaffolding; unreachable legacy surfaces are not silently reactivated or presented as rendered coverage.

Default authoring retains Build/Library/Setup and native tool navigation. Compact authoring uses Properties/Structure and a native tool Select. Visited panels and native Accordion content retain unfinished fields. Direct content precedes element metadata; structural commands sit in the contextual Element actions menu. Invalid retained fields take priority over canonical readiness and can reveal their owning control. Family variants begin at a declared structural change, show inheritance/reset state, and preserve raw override authority.

Original voucher document settings select Layout/Appearance/Document details/Sample values. Template choices use compact native Item rows. Empty documents present one insertion/template action. Stable portal hosts preserve library/inspector instances through native drawer dismissal and responsive docking. A narrow app-owned Preview/Export row complements native Page command overflow without replacing the header’s anatomy.

The 2.0.5 action/control roots are 32px, with small controls at 28px. `rounded-radius` uses the 12px radius root for controls/rows; `rounded-surface` uses four-thirds of that root (16px) for outer shells. Removed `rounded-inner` is not a current role. Cards retain normal 24px default insets and their library-owned regional anatomy. Creator, Editor and fixed-family Pages use md gutters/insets; the original voucher intentionally retains sm. Selection is rounded, padded, dashed editor geometry. Palette shortcuts use the current authored document’s colors rather than an unrelated fallback voucher palette.

The official copier publishes four canonical capabilities (components, tokenization, composition and design) plus the shared consumer bundle: five sibling skill directories and 81 assets in each project destination. Replaced managed copies are archived under `.cache/themelia-skills-backups`, outside discovery. Setup regression checks are available through `npm run test:ui-skills`.

The fresh source scope includes109 UI files:93 application files,7 consumer examples and9 mixed document/editor renderers. Pure authored renderers and dormant scaffolding remain separately recorded. Two exact authored-caption spacing findings are retained as named output exceptions, rather than changing document layout to satisfy an application-copy rule; new findings still fail. Eight warnings describe specialist drawing handles/toolbar buttons and the compact rich-text toolbar.

Fresh390/1440 light/dark captures cover24 base workspace states, with independent rendered scores17–19/20 and all blocking criteria passing after repairs. Opened drawers, nested palette, template application, invalid-draft review/focus, protected personalization and voucher modes have additional evidence. The root workspace design reports and artifacts record exact limits; real host requests, mailbox rendering and every exception state are not claimed by these fixture checks. Source audit, executed behavior and fresh appearance evidence remain separate, and no consuming host rollout is implied.

## Scope and owners

The family-review consumer follow-up renews only the two changed React examples and the supporting contracts input. Native conflict choices use text labels; compact property snapshots avoid rendering schema declarations ahead of changed values. Presence, truncation and mixed-type cues preserve meaning. Opening a saved review restores its operation, family and exact revision after freshness checks. Draft basis and published membership remain separate, and accepted publication updates the latter without replacing newer edits. Email previews use the authored target and reject compatibility errors before Apply. These application-owned examples do not add transport or lifecycle authority to the pure library.

The shared reachability boundary in [ui-scope.mjs](../scripts/ui-scope.mjs) starts at `src/main.tsx`, `src/index.ts`, `src/editor.ts`, `src/template-creator.ts` and seven supplied React consumer examples. The library-only frontend boundary check excludes example transport separately. The composition checker and inventory use the same boundary. Tests, unreachable compatibility scaffolding and authored document renderers are not UI compliance targets; the inventory lists excluded candidates and hashes reachable supporting code so changes still invalidate the review. Headless/rendering behavior is covered separately by package/schema/tests.

Review rule IDs below mean:

- `root`: provider defaults, theme and portal scope.
- `commands`: Page header roles, primary command and destructive confirmation.
- `layout`: Stack/Grid rhythm, one inset owner and app-owned placement/overflow.
- `copy`: native typography roles and passive content wrappers.
- `regions`: native Card/Item/fact/empty-state regions and semantic statuses.
- `control`: public props own dimensions, corners, focus, validation and disabled state.
- `overlays`: native modal/popover/menu lifecycle, insets, focus and dismissal.
- `adapter`: application value/callback/edit-policy adaptation without copied anatomy.
- `drawing`: authored output and application canvas geometry, described below.
- `editing`: the constrained inline HTML editing boundary, described below.

## Application boundaries and retained warning

**Inline HTML editing.** [rich-text-editor.tsx](../src/voucher-builder/ui/rich-text-editor.tsx) deliberately owns a constrained `contenteditable` lifecycle: only strong/emphasis/underline/link/line-break HTML, document-relative inline editing, DOM selection retention through a link dialog, blur/Enter commit, Escape cancellation and zoom-aware floating placement. Native Button, Card and ActionDialog still own its controls and surfaces. The compact floating Card retains the package checker’s `compact-card` warning: `padding="sm"` is an intentional 12px toolbar inset in 2.0.5, and public `style.containerType` disables unnecessary Card containment for intrinsic-width floating placement.

The public `features/rich-text-editor` family **does export `RichTextEditorToolbar` with configurable buttons**. It was considered, not overlooked. The full editor's `extraToolbarItems` adds after built-ins; its public props do not remove built-in formats or expose an editable-renderer/extension seam for this wire contract. Its standalone toolbar owns an embedded bottom-border/inset frame and does not expose the selection-preserving mouse/blur/ref hooks used by this floating editor. `base/inline-edit` supplies Input/Textarea with explicit save/cancel and a passive `renderValue`, not a custom editable renderer. Retaining this product-specific boundary avoids changing stored HTML, commit semantics or document layout. This is an explicit exception to all-native field anatomy, not an assertion that the native owners have no rich-text capability. Relevant installed declarations: `rich-text-editor.types.d.ts`, `partials/rich-text-editor-toolbar.d.ts` and `base/inline-edit/inline-edit.d.ts` under `dist/components/`.

**Canvas and authored output.** Paper size, document fills/borders/corners/fonts, frame previews, grid lines, fixed 20px SVG rulers with 7px numeric labels, drag hit areas, selection strokes and counter-scaled placement are application drawing geometry. The template element frame is a user-requested specialized control surface: compact native HTML buttons, explicit focus/disabled states, accessible names and keyboard navigation share a constrained action bar above the iframe. This is an explicit exception to native Button ownership, with an 8px padded, rounded dashed selection boundary and a softly raised toolbar. All selection colours use Themelia semantic tokens: muted-foreground, muted, primary, ring and their foreground pairs; radius and shadow-md own corners and elevation. The separate violet palette and corner marks are removed. Custom hover is pointer-gated, press scaling is reduced-motion-gated, and forced colors retain a system Highlight cue. Workspace panels/forms and removal confirmations retain native Themelia owners. The frame never wraps email table cells or enters authored/exported HTML/CSS. Rulers use semantic colors. Three fixed categorical debug washes/separators distinguish sections over the white output paper; they are diagnostics, not status/control colors. White print paper and its shadow stay independent of the surrounding dark workspace. Circular color samples display authored colors. These rules do not authorize styling native control descendants.

**Shell geometry.** Dock dimensions, structural separators, responsive reflow, scroll bounds and root-based panel insets are application layout. Template editing Pages use supported md gutters/insets; the original voucher uses sm. Native controls retain provider size/density/corner roles; native resource Cards retain normal surface insets. Host `className`, theme roots, custom field config and callbacks remain extension points requiring host validation.

## Invalidation and maintenance

Run `npm run check:ui-audit`. [audit-ui.mjs](../scripts/audit-ui.mjs) fails if the source inventory, source decisions, public contracts, package/guidance fingerprint, supporting import graph, dependency manifests, local UI policy/contributor guidance or audit tooling differ from the reviewed state. It also rejects ledger files outside the current scope. `npm run verify` includes this check.

After a change:

1. Read the changed owner declarations and relevant consumer recipe; inspect dynamic adapters, render slots and CSS as well as direct imports.
2. Run `node scripts/audit-ui.mjs --inventory` to regenerate only the inventory.
3. Review the diff and update the affected manual decisions/fingerprints in `ui-compliance.review.json`. There is deliberately no command that auto-approves source changes.
4. Run the composition check, audit, typecheck and relevant tests; inspect affected rendered states. Update this guide's scope/evidence when it changes.

This is a drift guard and review record, not a semantic proof. A manually accepted poor decision can still pass; the audit does not replace human review, browser testing or accessibility assessment.
